# US-028 Restore Defaults demo

Open `/?source=manual`. First change a setting away from factory: press the wrench (setup), pick X, scroll ▼ to `bEEP on`, press ◀/▶ to `bEEP oFF`, press C to exit. Now restore: re-enter setup, pick X, scroll ▼ to `rSt oEm`, press ENT → `In ProG` (the restore runs); after a brief dwell the display returns to the normal readout. Re-enter setup and check `bEEP` — it's back to `bEEP on` (factory default); any SDMs / tool offsets are cleared.

OEM-baseline path (closes US-044 AC44.4): if you first captured an OEM baseline via `oEm mod` (password `3 5 7 2 6` → `StorEd`), `rSt oEm` restores to THAT baseline instead of the factory defaults.

## AC reconciliation (manual tie-breaker)

The el400-operation-manual §6.2 (the user-designated tie-breaker) lists `r5t oEñ` (restore, line 482, **no** password marker) and `oEñ ñod` (OEM mode, line 483, "Password protected") as two **separate adjacent** rows. The story's restore confirm chain conflated them. Mapping of the deviating ACs (documented, not dropped):

- **AC28.4 (password 3 5 7 2 6)** — the password guards *defining* the baseline (US-044 `oEm mod`), not *restoring* to it. Restore is not password-gated per §6.2 line 482.
- **AC28.5 (3 AXIS / MILL / OPT OFF)** — not applicable: these are model/options glyphs (§12 glossary, `oPt oFF` line 2097), not a restore confirm chain.
- **AC28.6 (SAV CHG on restore)** — not a separate step; `rSt oEm` persists the restored config directly on ENT.
- **AC28.8/28.9 (IN PROG / 2-min wait)** — a brief test-controllable `In ProG` dwell, not a real sleep (panel font has no uppercase 'N', so `IN` renders `In`).
